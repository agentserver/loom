# `tests/eval/motivation/` — p3-mini-case scaffold

This package is the **harness-only** deliverable of the
`paper/v3/p3-mini-case` worktree. It contains:

- Four canonical-schema collectors (`collect_contexts_count.py`,
  `collect_wrong_context_failure.py`, `collect_manual_steps.py`,
  `collect_reuse_time_savings.py`).
- `aggregate.py` — merges N raw JSON into `(median, iqr_low, iqr_high)`
  using `statistics.quantiles(..., n=4, method="exclusive")`.
- `gen_provenance.py` — fills the paper-side
  `paper_outputs/motivation_data_provenance.md.template` (a template only in
  this worktree; the real filled MD is generated by `p3-mini-case-run`).
- `replace_intro.py` — **dual-target** dry-run patcher. Handles
  `paper_outputs/introduction_v3.md` (anchor+regex mode) AND
  `paper_outputs/motivation_v3.md` (`{{placeholder}}` mode) in a single
  invocation. Under this worktree it is only ever invoked with `--dry-run`;
  `--execute` requires `ALLOW_INTRO_REWRITE=1` and is deliberately gated.
- `dry_run_smoke.sh` — end-to-end scaffold self-check: 4 collectors → 3 raw
  files per key → aggregate → gen_provenance (`--dry-run`) → replace_intro
  (`--dry-run --allow-scaffold-smoke-input`) → two diff hunks to stdout,
  neither paper file mutated.
- `results/dry_run_smoke/*.json` — the 4 committed fake aggregate JSON
  produced by the smoke chain (evidence the scaffold runs green).
- `tests/` — pytest suite covering every spec §5 test row and every safety
  item §7 (a)–(k).

**What this worktree does NOT do**:

- **Independently sample the 4 numbers.** Real numbers come from the
  `p3-stub-fulltable-run` main experiment metric directory
  (唯一数据源约定, `paper_outputs/evaluation_v3.md` §6.7).
- **Backfill `paper_outputs/introduction_v3.md` §motivation** or
  **`paper_outputs/motivation_v3.md`**. Both paper files are at
  `git diff = ∅` at commit time. Backfill is `p3-mini-case-run`'s
  responsibility; `replace_intro.py` is invoked there once with
  `--target introduction_v3.md --target motivation_v3.md` (single
  invocation, both files, atomic rollback on any per-target failure).

The `motivation-e2e` workload lives at
`tests/eval/workloads/motivation-e2e/`; its `spec.yaml`'s first line
declares "scaffold self-check only; NOT part of §6.3 main experiment
5-workload set" so its `id` cannot leak into the `p3-stub-fulltable` main
table.
