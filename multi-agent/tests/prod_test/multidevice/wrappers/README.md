# Multi-device startup wrappers

Each wrapper marshals CLI args + `LOOM_DEPLOY_MODE` env into a call to
Phase 2 `deploy.sh` (Linux) or `deploy.ps1` (Windows). The wrappers do
NOT edit or replace the Phase 2 deploy scripts — they call them as
subprocesses.

## Scope (harness-only)

- `LOOM_DEPLOY_MODE=stub` (default) → wrapper calls the Phase 2 deploy
  script with `--mode stub`, which runs against the local
  `agentserver-stub`.
- `LOOM_DEPLOY_MODE=prod` → wrapper checks `ALLOW_PROD_DEPLOY=1`. If
  the env is NOT set (the case in this worktree, always), the wrapper
  silently downgrades to `--mode stub` and warns on stderr.
- `dry_run_all.sh` never sets `ALLOW_PROD_DEPLOY`. Real prod deploy
  execution is deferred to `paper/v3/p3-prod-multidevice-run`.

## Examples

```bash
# Laptop (driver)
bash laptop_up.sh --config ../laptop.yaml.template

# Headless (observer + slave-A)
bash headless_up.sh --config ../headless.yaml.template

# Cloud (slave-C; print-only vendor provisioning)
bash cloud_up.sh --config ../cloud.yaml.template

# Windows (slave-B)
pwsh -File windows_up.ps1 -Config ..\windows.yaml.template
```

## Bind endpoint contract

Every wrapper binds `127.0.0.1:<port>`:

| Wrapper | Port |
|---|---|
| laptop_up.sh    | 18092 (driver) |
| headless_up.sh  | 18091 (observer) + 18093 (slave-A) |
| cloud_up.sh     | 18093 (slave-C on remote droplet) |
| windows_up.ps1  | 18094 (slave-B) |

No wildcard binds (`0.0.0.0:`, `[::]:`, external IPs) are ever
generated by the wrappers — enforced by
`tests/test_bind_endpoints.py`.
