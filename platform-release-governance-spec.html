一条清晰的治理边界

外部平台治理决定“是否批准”；Observer 只验证、持久化并执行受约束的指针切换。

任何 workspace user、agent token、Chat Web、Driver MCP、Slave 或 coding agent 都不能创建、批准或直接改写 active-default。

01 · 平台 pipeline构建 release

产出不可覆盖、内容寻址的 schema、manifest、handler bundle、fixture 与 generator identity。

02 · 验证证据验证 / 预检

promotion 要全量验证；rollback 只做精确 bundle 与 ABI 兼容性预检。

03 · 外部治理系统人工批准

一名 platform_release_operator 签发带平台认证证据的批准证明。

04 · Observer持久化并 CAS

验证证明，存入 registry；受信 pipeline 仅执行 expected → target 的原子 CAS。

05 · 新 run选择新默认

只有之后成功 open_run 的 run 使用新 release；既有 pin 永不改写。

外部系统不是 AgentServer、workspace UI 或本项目的新 token 类型；它只向 Observer 提供可验证的平台认证 evidence ref。

本页的“平台事件”仅指 RunControlSchemaRelease 的 promotion / rollback / active-default 变更及其验证、审批和审计。

这些 release-governance 事件绝不写入任一用户 RunEvent。public capability candidate 的 fixture 认证是另一条 owner-scoped、非用户 Run 的 platform-control-plane 流程：仍开放的 origin Run 可按主规范接收受控失败事件；仅当 candidate owner 仍为 active、来源会话被强制关闭后，结果才改入 owner candidate 状态页。User disable 则优先终止／撤回该 owner 的认证中 candidate，不生成 owner-status 或 RunEvent 回传，重新启用也须以新 candidate digest 和新 owner approval 重提。这不属于本页的 RunControl release 事件例外。

谁负责什么

外部平台治理

批准或拒绝，而非执行

  • 认证平台运维人员。
  • v1 恰好一名 platform_release_operator。
  • 对精确 request 签发 approval attestation，或提交带 reason code 的明确 rejection；两者都带 authentication evidence。
  • 不能写 Observer pointer、不能改 release 或 evidence。
平台 release pipeline

验证，而非自批

  • 生成不可变 release 与验证 evidence。
  • 创建 pending change request。
  • 读取批准证明并执行原子 CAS。
  • 不持有 workspace user / agent 权限。
Observer

注册、校验、审计

  • 保存 release registry、approval 与 pointer。
  • 独立验证 attestation / evidence binding。
  • 拒绝陈旧、过期或冲突的变更。
  • 绝不把本页 RunControl release 治理事件写入任一 RunEvent。
workspace 运行时

只消费 pin

  • 新 run 从唯一默认 release 固定 version / digest。
  • 既有 run 使用自己的 immutable pin。
  • Chat Web 不能显示或操作平台批准卡。
  • Driver / Slave 无法触发 pointer 修改。

这些对象位于 Observer 的平台治理 registry，不属于 workspace 的 run、ApprovalRequest 或 Chat Web 数据模型。

Promotion：候选 release 成为默认版本

构建不可变候选

pipeline 生成 release manifest、schema、全部 MCP / Observer / UI handler、fixture 与 generator identity；候选只能新增，不能覆盖已有 digest。

取得全量 pass 证据

PromotionValidationEvidence=pass 必须同时覆盖 schema / manifest / signature / digest、全部生成物、fixture、契约测试与 generator compatibility check。任一失败：不提升、不写本页 RunControl release 的 RunEvent、不触碰 run。

创建待批准变更

Observer registry 创建 pending PlatformReleaseChangeApproval，固定 operation、expected-current、target、evidence ref、build identity 与 24 小时 expires_at。

外部平台治理批准或拒绝精确 request

恰好一名平台内部 platform_release_operator 作出决定。批准时，外部治理系统提交 operator identity、platform-authentication evidence 与时间；拒绝时还提交 closed-enum reason code，并把 request 原子置为 rejected。两种决定都不能直接调用 pointer 写入接口；rejected request 不能恢复、批准或执行，未来重提必须创建新的 approval ID。

受信 pipeline 进行 CAS

Observer 验证 approval binding 后，pipeline 执行 CAS(expected_current_digest → target_release_digest)。成功时 approval consumed，并写 run_control_active_default_changed 平台审计。

External governance ── signed approval attestation ──> Observer platform registry
Observer ── verified immutable refs ──> trusted release pipeline
pipeline ── CAS(old → target) ──> active-default pointer

Rollback：回到曾成功 promotion 的 retained release

与 promotion 相同的部分

仍需建立 PlatformReleaseChangeApproval、由外部平台运维显式批准或拒绝、24 小时 TTL、批准后的 exact expected-current CAS 和完整平台审计。拒绝是该 request 的终态，pointer 不变；回滚不是自动故障转移，也不会修改既有 run。

与 promotion 不同的部分

不重跑历史全量 fixture / contract suite。它只要求 RollbackCompatibilityPreflight 证明 retained manifest / signature / digest / bundle 完整，以及当前 Observer / Driver ABI 能加载精确 handler。

回滚预检失败不是 RunControl run 事件。pointer 保持不变；只写 AuditRecord(type=run_control_active_default_change_failed, operation=rollback) 并通知平台运维。任何 run、dispatch、attempt 与 RunEvent 都不受影响；这不改变主规范中 public candidate 的独立 owner-scoped 认证结果回传。

PlatformReleaseChangeApproval 状态

PENDING验证 / 预检已 pass；等待外部治理系统的单人决定（批准或拒绝）。尚不能切换。
APPROVED认证证据、operator ID 与 approved_at 已持久化；等待 pipeline 执行一次 CAS。
CONSUMEDCAS 成功，pointer 已更新；成功审计记录 old / target、evidence、approval、operator、build identity。
REJECTEDoperator 对精确 request 明确拒绝；保存 actor、authn evidence、rejected_at 与 closed-enum reason code。pointer 不变，该 approval ID 永不可恢复、批准或消费；以后重提必须使用新 ID。
EXPIRED24 小时到期。只写平台审计；不切换、不影响 run。需要新 approval ID 才能继续。
CONFLICTED当前 pointer 不再等于 expected-current；拒绝旧批准，写失败审计。需新 request + 新批准。

状态转换以同一 approval ID 串行化：PENDING 只可进入 APPROVED、REJECTED 或 EXPIRED；APPROVED 只可进入 CONSUMED、CONFLICTED 或 EXPIRED，不能再被拒绝。任何终态后的批准或执行都必须拒绝。

v1 验收不变量

可证明的隔离

平台批准不是 user token、agent token、workspace role、Chat Web 操作或 Driver MCP tool。它没有被 LLM 读取、生成、重放或解释的路径。

可证明的版本固定

每个新 run 只在 open_run 成功事务中 pin 当时的唯一默认 release；默认切换永不改写已 open 或已 closed run 的 version / digest。

可证明的单写者

只有受信 pipeline 能以 CAS 改 pointer；平台运维只能批准或拒绝 immutable request。所有成功、验证失败、明确拒绝、过期和冲突均有平台审计。

明确延期的能力

双人 / N-of-M 签核、职责分离、平台运维控制台与用户 / workspace 自定义 run-control 协议均不属于 v1。
