一条清晰的治理边界

外部平台治理决定批准或拒绝；Observer 验证并持久化决定，且仅在批准者当前权限仍有效时允许受约束的指针切换。

除本页明确限定的空 registry 一次性 genesis 外，任何 workspace user、agent token、Chat Web、Driver MCP、Slave 或 coding agent 都不能创建、批准或直接改写 active-default；genesis 成功后，所有后续变更也只能走本页普通 promotion / rollback。

01 · 平台 pipeline构建 release

产出不可覆盖、内容寻址的 schema、manifest、handler bundle、fixture 与 generator identity。

02 · 验证证据验证 / 预检

promotion 要全量验证；rollback 只做精确 bundle 与 ABI 兼容性预检。

03 · 外部治理系统人工决定

一名 platform_release_operator 对精确 request 批准或拒绝，并提交平台认证证据。

04 · Observer持久化、重验并 CAS

持久化决定；仅对 approved request 重验批准者当前权限与全部 binding 后，才允许受信 pipeline 执行 expected → target 的原子 CAS。

05 · 新 run选择新默认

只有之后成功 open_run 的 run 使用新 release；既有 pin 永不改写。

外部系统不是 AgentServer、workspace UI 或本项目的新 token 类型；它只向 Observer 提供可验证的平台认证 evidence ref。

本页的“平台事件”仅指 RunControlSchemaRelease 的 promotion / rollback / active-default 变更及其验证、审批和审计。

这些 release-governance 事件绝不写入任一用户 RunEvent。public capability candidate 的 fixture 认证是另一条 owner-scoped、非用户 Run 的 platform-control-plane 流程：仍开放的 origin Run 可按主规范接收受控失败事件；仅当 candidate owner 仍为 active、来源会话被强制关闭后，结果才改入 owner candidate 状态页。User disable 则优先终止／撤回该 owner 的认证中 candidate，不生成 owner-status 或 RunEvent 回传，重新启用也须以新 candidate digest 和新 owner approval 重提。这不属于本页的 RunControl release 事件例外。

接口、错误、扩展与依赖健康的治理边界

RunControl active-default 只选择任务控制 release；它不能偷偷改变跨组件错误语义、扩展 authority、策略应用时点或基础设施 degraded-mode policy。

每个受信 deployment 固定 immutable InterfaceContractBundle、DeploymentCompatibilityManifest 与独立的 DeploymentConfigurationIdentity。前者除 Web OpenAPI、Worker / DriverControl protobuf 与 Driver MCP schema 外，还固定 DomainErrorEnvelope、ExtensionGovernanceMatrix 和 PolicyApplicationMatrix；manifest 固定 exact DependencyHealthPolicy digest、组件支持范围和 DB schema compatibility range；configuration identity 只固定 DB、Object-Lock、KMS、OIDC、dependency-policy 等非 secret 配置类别的 opaque identity / digest，绝不保存 credential、原始 endpoint 或本机配置正文。三者随 deployment build / SystemConformanceEvidence 发布；configuration identity 漂移也必须取得新 evidence，且均不由 user token、agent token、WorkspacePolicy、ParentContract、Driver MCP、public package 或本页 RunControl pointer 修改。

契约必须固定的内容变更与 unknown handling
DomainErrorEnvelopecode、category、retry class、safe typed details、operation / authority ref、Retry-After、correlation 与 allowed-next-actions；HTTP、gRPC、MCP 只作协议映射。随 InterfaceContractBundle / component build 生成并通过跨协议 golden fixture。tool-specific details 只能收紧；原始 exception / provider payload 不能成为兼容接口。错误 envelope 的不兼容变更要求新的 interface-contract range，不借 RunControl release 无感改变。
ExtensionGovernanceMatrix逐类覆盖 Node kind、Artifact kind、Approval action kind、DecisionDefinition、RunEvent type、resource kind 与 public capability key 的 authority、创建主体、compatibility、unknown behavior、schema / handler / fixture / evidence、promotion / revoke 路径。authority-bearing unknown 值一律 fail closed；仅矩阵明列的 display-only additive field 可忽略。矩阵不创建万能插件 registry：各类型仍走其既有 RunControl release、ArtifactKindRegistry 或 PlatformCatalogChangeApproval 等治理路径。矩阵自身的不兼容变更属于新的 InterfaceContractBundle / deployment build，并须取得 SystemConformanceEvidence=pass。
PolicyApplicationMatrix逐 policy key 固定 authority、version source、evaluation point、pinned|current_rechecked、收紧／放宽对既有对象的效果、重新验证要求和 AuditRecord / RunEvent 行为；至少覆盖 PlanLimits、WorkspacePolicy、WorkerLivenessPolicy、CodingAgentLivenessPolicy、ChatTransportLimits、LLMInlinePayloadPolicy、Artifact caps / quota、ControlPlaneAdmissionLimits、retry / backoff、DependencyHealthPolicy、ControlPlaneStorageCapacityPolicy 与 staging-abandon policy。这是穷尽、规范性的表：每个被 v1 handler、validator、scheduler 或 UI 消费的 key 必须恰有一行。缺行、重复、unknown key、缺 evaluation semantics 或与正文 authority 冲突必须使对应 build conformance fail；矩阵不保存某个 Run 的全量策略值，也不创建 PlatformPolicySnapshot。变更属于新的 InterfaceContractBundle / deployment build，不能借 RunControl pointer、WorkspacePolicy 或 LLM 无感改变。
DependencyHealthPolicyobject storage、KMS / Vault、OIDC、LLM provider、DB / durable ledger 的 route gate、timeout / circuit-breaker profile、安全错误与恢复门。随 DeploymentCompatibilityManifest 固定并使用成熟 health-check / breaker 实现；变更须新 build / config digest 与 conformance，不是 Run、LLM 或 workspace 可配置 policy。局部故障只关闭受影响 route；DB / ledger 领域写 fail closed，stale cache 不能裁决授权或完成。
DeploymentConfigurationIdentity非 secret 的 configuration category、opaque provider ref / digest、当前 deployment build / manifest / conformance binding。独立于 software manifest 的 platform registry 对象；DB、Object-Lock、KMS、OIDC issuer / allowlist 或 dependency-policy profile 变化必须形成新的 configuration digest 并完成 conformance。它不能携带 credential、用户内容、host path 或临时运行状态，不能被 RunControl pointer 或 workspace policy 改写。
RunControlSchemaRelease compatibility候选 release 使用的 node / decision / event / approval 等 authority-bearing 类型必须全部存在于当前 ExtensionGovernanceMatrix，并携带矩阵要求的 handler、fixture、generator 与 evidence。promotion / rollback preflight 都要验证 exact extension-matrix compatibility；unknown、缺 handler 或证据不全固定拒绝。通过后仍只改变 active-default，InterfaceContractBundle、ExtensionGovernanceMatrix、PolicyApplicationMatrix 与 DependencyHealthPolicy 均不随 pointer 漂移。

Deployment build、SigningKey 与紧急安全处置

deployment 的可信性和 RunControl pointer 是两条不同治理线。

本节只治理受信 build / behavior bundle 的安全可用性与签名根；它不自动改写既有 Run pin、Conversation profile 或 active-default。

DeploymentMaintenanceGate 是唯一 deployment-level 安全准入门

每个 deployment 恰有一个持久化 DeploymentMaintenanceGate，带单调 observer_recovery_epoch；每个恢复、checkpoint、配置、schema 或安全问题都以 immutable DeploymentMaintenanceRecord 追加为一个 active cause，并固定证据与 exit verifier。任一 cause active 时拒绝正常业务写入；平台人员只能修复依赖并触发对应 verifier，不能手工删除 cause、force-ready 或借 RunControl pointer 绕过。所有 cause 的 verifier pass 后才退出 maintenance。它不是 Workspace disable、Run pause、user / agent token 权限或用户 RunEvent。

SigningKey 生命周期与长期验证材料

SigningKey 由 Observer platform registry 保存 typed usage、public verification material、algorithm / canonicalization / verifier-profile、KMS handle ref、创建审计和状态 active → retiring → revoked。只有 active key 可签发新 package / deployment attestation；retiring 停止新签发，私钥 / KMS handle 可在明确 overlap / retention 后退役，但被永久 AuditCheckpoint、package 或 deployment evidence 引用的公开验证材料必须继续可验证。revoked key 不得新签发；历史验证按 usage、证据发生时间和已声明的泄露处置执行。算法迁移只能产生新的 evidence / verifier profile，不能重签或静默替换旧 evidence。

KeyCompromiseAssessment 先精确评估，再处置

疑似 key 泄露必须生成 immutable KeyCompromiseAssessment，固定 key、发现时间／影响窗口、证据 ref、assessment revision 与精确受影响的 package / deployment / checkpoint digest 集合。新证据只能追加新的 assessment revision，不能覆盖旧结论。assessment 可暂停相应用途的新签发，并只驱动既有 CapabilityRevocation、DeploymentSafetyAdvisory 或 maintenance；不得 blanket-revoke 所有历史对象、把 key rotation 当作补救，或伪造普通 RunEvent。

配置身份漂移必须重新 conformance

DeploymentConfigurationIdentity 独立于 software manifest，固定 deployment 当前 DB、Object-Lock、KMS、OIDC、dependency-policy 等非 secret 配置类别的 opaque identity / digest。任何受信配置改变都必须产生新 digest，并由 exact configuration binding 的 SystemConformanceEvidence=pass 验证后才可 ready；未知、缺失或漂移进入 maintenance / update_required。它不保存 credential、用户内容、host path 或临时健康值，也不允许 user、agent、LLM、WorkspacePolicy 或 RunControl pointer 修改。

DeploymentSafetyAdvisory

平台受信维护流程可为精确 component-build 或 CodingAgentBehaviorBundle digest 写 immutable DeploymentSafetyAdvisory，包含 severity、reason code、evidence ref 与 audit。critical advisory 立即拒绝受影响 build 的新 session / turn；主规范定义它与 capability_revoked 为仅有的 v1 automatic must_yield delivery class。它不 silent-migrate profile / bundle、Conversation 或 Run；当前 generation 的停止走主规范本机 supervisor / evidence 路径，恢复必须显式 maintenance 处置或新 Conversation。

发布证据与到期工作

SystemConformanceEvidence=pass 必须绑定 exact configuration identity，并覆盖 PolicyApplicationMatrix 完整性（含 CodingAgentLivenessPolicy）、同一 durable due-work / outbox 模型的 leader failover、maintenance multi-cause / no-bypass、restore observer_recovery_epoch / unmatched-report reconciliation、storage reserve、staging abandon、SigningKey overlap / compromise assessment / long-term public verification、critical advisory、AuditCheckpoint continuity / restore、UsageLedger 无正文去重、environment evidence / reproducibility boundary、resolver integrity-mode、package retention / advisory、Artifact tombstone non-resurrection、expand-contract migration、attention / cross-view projection 与 IdP-only / no-erasure fixture。普通 RunControl promotion / rollback 只改变 active-default；它们不能绕过 advisory、key 状态、configuration identity 或 deployment maintenance gate。

不会污染用户 RunEvent

SigningKey、deployment advisory、SystemConformance 与其安全审计属于平台／deployment control plane。它们不被伪造成 release-pointer 变更或普通 RunEvent；只有主规范已经定义的、精确受影响的 run safety decision 才能以其自己的结构化规则通知绑定 coding agent。

AuditCheckpoint 是 WORM 而非“DB append-only”的口头承诺

可查询 AuditRecord 表只是操作副本。平台周期性对有序 audit range 计算 Merkle / hash root，连同 ledger schema / deployment identity、configuration identity、SigningKey / verifier-profile ref 与 signature 写入 immutable AuditCheckpoint，并保存在成熟 Object-Lock / WORM storage。checkpoint 只含 metadata / digest；任何断档、无效签名、缺失历史公开验证材料或 root 不符都必须进入 maintenance，不能自动重签、补洞或静默继续信任。

公共包安全公告只提供证据，不暗中扫描私有内容

PackageSecurityAdvisory 仅由平台人工为 exact public package digest 记录 finding code 与 evidence ref。它不读取、扫描或推断 personal package source，也不自动删除 package payload；受权 PlatformOperator 只能根据该公告另行建立现有 CapabilityRevocation。revoke 仍 gate 新 use，却保留 audit / reproducibility 所需 bytes。

数据库升级为前向 expand / contract，绝不以 RunControl rollback 回滚数据

deployment 使用成熟 migration library：expand 在声明的 DB schema compatibility window 内发布；contract / destructive migration 必须 maintenance、restore checkpoint 且旧 build 已不再服务。v1 不自动 down-migrate。RunControl active-default rollback 仅切换后续 run 的 release pointer，不回滚 build、behavior bundle 或数据库；不兼容时保持 maintenance / update_required。

Genesis：空平台唯一的一次性启动例外

Genesis 只解决“尚无 Operator、active-default 与 signing trust，因而无法开始正常治理”的启动环；它不是永久管理接口。

该操作只由 deployment-scoped CLI / job 在平台 bootstrap_pending 时执行，认证依赖部署环境的 OS / cloud IAM 与 KMS trust，不接受 user token、agent token、OIDC browser session、Chat Web、Driver MCP、Slave、LLM 或普通 release pipeline 请求。bootstrap pending 期间只开放无内容 health 与该部署入口，拒绝普通登录 token 签发、Workspace / Agent / Conversation / Run 与 worker traffic。

加载并验证完整 genesis bundle

bundle 固定 deployment identity、当前 DeploymentCompatibilityManifest / InterfaceContractBundle digests（含 DomainErrorEnvelope / ExtensionGovernanceMatrix / PolicyApplicationMatrix）、exact DeploymentConfigurationIdentity 与 DependencyHealthPolicy digest、绑定 exact component builds / configuration identity 的 SystemConformanceEvidence=pass、预置于 KMS / secret manager 的 signing-key handle / public verification metadata、精确初始 operator (issuer,subject)、不可变默认 WorkspacePolicy template、首个 RunControlSchemaRelease bundle 及其完整 PromotionValidationEvidence=pass。系统 conformance、RunControl promotion 与 public capability fixture 是三条独立证据链，不能互相代替；issuer 必须在受信 allowlist，deployment contract 的 policy-application fixtures 与 release 的 schema、manifest、handler、fixture、generator、签名、digest、当前 ExtensionGovernanceMatrix / ABI 均须使用各自既有 validator 全量验证。任何字段缺失、digest / build / configuration binding 冲突、unknown authority-bearing type、未定义 policy application、conformance 非 pass、KMS key 不可用或验证失败都在写 DB 前终止。

证明 registry 确实为空

Observer 在 serializable transaction / 全局 bootstrap lock 下重新检查：不存在 PlatformGenesisRecord、User / ExternalIdentityLink、PlatformOperatorAssignment、SigningKey registry、RunControlSchemaRelease、active-default、DefaultWorkspacePolicyTemplate、Workspace、Agent、Conversation 或 Run 事实。任一对象存在即返回 genesis_not_empty，不能覆盖、合并、补写或把既有平台重新初始化。

一个事务建立最小可信根

Observer 原子写入 SigningKey public verification metadata、初始 User(status=active) 与精确 ExternalIdentityLink、唯一 active PlatformOperatorAssignment、immutable DefaultWorkspacePolicyTemplate + active pointer、已验证 RunControlSchemaRelease / evidence、active_default_release_digest、当前 deployment / configuration / interface-contract / ExtensionGovernanceMatrix / PolicyApplicationMatrix / DependencyHealthPolicy digests、匹配的 system-conformance pass evidence ref、初始 DeploymentMaintenanceGate(observer_recovery_epoch=0, no active cause) 和唯一 PlatformGenesisRecord。初始 pointer 直接绑定 bundle 中已全量 pass 的精确 release，不创建虚假的 PlatformReleaseChangeApproval，也不声称由尚未存在的 Operator 批准。

提交后永久关闭 bootstrap

只有整个 DB 事务成功才从 bootstrap_pending 进入 normal；KMS 中预创建但未被成功引用的 key 不构成已初始化平台。成功的 genesis record 是永久 fence：同一或不同 bundle 的任何再次调用都固定拒绝并审计，不存在 reset、delete、rollback-to-empty 或第二个 genesis。首个 operator 后续通过正常 OIDC 登录命中预建 link；之后新增 User 走主规范的受信 OIDC JIT，所有 active-default 变化走普通 promotion / rollback。

这是现有单写者规则的唯一、明确且不可重复的例外。 Genesis 不写任何用户 RunEvent，不创建 Workspace、Agent、Conversation、Run、ApprovalRequest 或 capability candidate。它只创建平台开始执行普通治理所需的可信根；一旦提交，“只有受信 pipeline 在 active Operator 的精确批准后以 CAS 改 pointer”立即成为没有例外的永久规则。

谁负责什么

外部平台治理

批准或拒绝，而非执行

  • 认证平台运维人员。
  • v1 恰好一名 platform_release_operator。
  • 对精确 request 签发 approval attestation，或提交带 reason code 的明确 rejection；两者都带 authentication evidence。
  • 不能写 Observer pointer、不能改 release 或 evidence。
平台 release pipeline

验证，而非自批

  • 生成不可变 release 与验证 evidence。
  • 创建 pending change request。
  • 请求 Observer 重验批准者当前权限与批准证明，通过后才执行原子 CAS。
  • 不持有 workspace user / agent 权限。
Observer

注册、校验、审计

  • 保存 release registry、approval 与 pointer。
  • 独立验证 attestation / evidence binding。
  • 拒绝陈旧、过期或冲突的变更。
  • 绝不把本页 RunControl release 治理事件写入任一 RunEvent。
workspace 运行时

只消费 pin

  • 新 run 从唯一默认 release 固定 version / digest。
  • 既有 run 使用自己的 immutable pin。
  • Chat Web 不能显示或操作平台批准卡。
  • Driver / Slave 无法触发 pointer 修改。

DeploymentSafetyAdvisorydeployment_safety_advisory_id；exact component-build / behavior-bundle digest、severity、reason code、evidence ref、created / resolved audit。deployment control plane 权威保存。critical advisory gate 新 session / turn，并按主规范触发精确的 safety wake；不替换已 pin profile、不改写 Run 或 active-default。
AuditCheckpointaudit_checkpoint_id；有序 audit range、Merkle / hash root、ledger schema / deployment / configuration identity、SigningKey / verifier-profile ref / signature、immutable Object-Lock / WORM storage ref。Observer platform audit registry 与成熟 WORM/Object-Lock store 共同保存；可查询 AuditRecord DB 表只是操作副本。checkpoint 只含 metadata / digest，不含 Prompt、Artifact bytes 或业务正文；continuity / signature / root / historical verifier 验证失败必须进入 maintenance，不能重签或静默信任。

RunControlSchemaReleaserun_control_schema_digest + immutable version；schema、manifest、handler bundle、fixture、generator digest。平台 release pipeline 产出；registry 只读保存。旧 release 因既有 Run / RunEvent / AuditRecord retention 或 legal hold 而继续可解析。
PromotionValidationEvidence内容寻址 evidence_ref；绑定 candidate digest、manifest、签名、全量生成物、fixture、契约测试、generator 与当前 ExtensionGovernanceMatrix compatibility。promotion 的唯一 pass 前提；unknown authority-bearing type、缺 handler / fixture / evidence 或矩阵不兼容都失败且不创建 pointer 变更。证据不可原地修改，条件变化必须产生新的 evidence。
RollbackCompatibilityPreflight内容寻址 evidence_ref；绑定 retained target、manifest / signature / bundle 完整性、当前 ExtensionGovernanceMatrix 与 ABI。rollback 的唯一 pass 前提；不重跑历史全量 suite，但必须 fail closed 验证 retained release 的全部 authority-bearing type 在当前矩阵 / handler 中可解释。预检失败不改变默认版本。

active-default pointer唯一 active_default_release_digest，无 user / workspace scope。空 registry genesis 事务只可初始化一次；此后仅 pipeline 在批准后以 CAS 改写。一次成功切换只作用于之后新开的 run。
AuditRecordaudit_id；关联 release、approval、operator、pipeline build、evidence、old / target digest。本页 RunControl release 的平台级 append-only、可查询审计副本；其 tamper-evidence 由周期性 signed AuditCheckpoint + Object-Lock / WORM storage 提供。不是 RunEvent，不能被 coding agent 读取成任务语义事件；这不重定义主规范中 public candidate 的 owner-scoped 认证结果回传。

Promotion：候选 release 成为默认版本

构建不可变候选

pipeline 生成 release manifest、schema、全部 MCP / Observer / UI handler、fixture 与 generator identity，并枚举该 release 使用的全部 authority-bearing extension values；候选只能新增，不能覆盖已有 digest。

取得全量 pass 证据

PromotionValidationEvidence=pass 必须同时覆盖 schema / manifest / signature / digest、全部生成物、fixture、契约测试、generator compatibility 与当前 ExtensionGovernanceMatrix compatibility check。任一 unknown authority-bearing type、缺 handler / fixture / evidence 或其他失败：不提升、不写本页 RunControl release 的 RunEvent、不触碰 run。

创建待批准变更

Observer registry 创建 pending PlatformReleaseChangeApproval，固定 operation、expected-current、target、evidence ref、build identity 与 24 小时 expires_at。

外部平台治理批准或拒绝精确 request

恰好一名平台内部 platform_release_operator 作出决定。批准时，外部治理系统提交 operator identity、platform-authentication evidence 与时间；拒绝时还提交 closed-enum reason code，并把 request 原子置为 rejected。两种决定都不能直接调用 pointer 写入接口；rejected request 不能恢复、批准或执行，未来重提必须创建新的 approval ID。

受信 pipeline 重验权限并进行 CAS

Observer 在消费 approved record 时重新验证其绑定的 exact PlatformOperatorAssignment 仍 active，且关联 User 仍 active；失败则把 approval 原子置为 invalidated 并拒绝 CAS。它还必须确认 deployment 未因 AuditCheckpoint continuity / signature / root failure 处于 maintenance。只有 authority、approval binding、TTL、checkpoint health 与 expected-current 全部通过，pipeline 才执行 CAS(expected_current_digest → target_release_digest)；成功时 approval consumed，并写 run_control_active_default_changed 平台审计。

External governance ── signed approval attestation ──> Observer platform registry
Observer ── current authority + immutable refs ──> trusted release pipeline
pipeline ── CAS(old → target) ──> active-default pointer

Rollback：回到曾成功 promotion 的 retained release

与 promotion 相同的部分

仍需建立 PlatformReleaseChangeApproval、由外部平台运维显式批准或拒绝、24 小时 TTL、批准后的 exact expected-current CAS 和完整平台审计。拒绝是该 request 的终态，pointer 不变；回滚不是自动故障转移，也不会修改既有 run。

与 promotion 不同的部分

不重跑历史全量 fixture / contract suite。它只要求 RollbackCompatibilityPreflight 证明 retained manifest / signature / digest / bundle 完整、当前 Observer / Driver ABI 能加载精确 handler，并且 retained release 使用的全部 authority-bearing extension values 仍可由当前 ExtensionGovernanceMatrix / handler fail-closed 地解释。

回滚预检失败不是 RunControl run 事件。pointer 保持不变；只写 AuditRecord(type=run_control_active_default_change_failed, operation=rollback) 并通知平台运维。任何 run、dispatch、attempt 与 RunEvent 都不受影响；这不改变主规范中 public candidate 的独立 owner-scoped 认证结果回传。

PlatformReleaseChangeApproval 状态

PENDING验证 / 预检已 pass；等待外部治理系统的单人决定（批准或拒绝）。尚不能切换。
APPROVED认证证据、operator ID 与 approved_at 已持久化；等待 pipeline 执行一次 CAS。
CONSUMEDCAS 成功，pointer 已更新；成功审计记录 old / target、evidence、approval、operator、build identity。
REJECTEDoperator 对精确 request 明确拒绝；保存 actor、authn evidence、rejected_at 与 closed-enum reason code。pointer 不变，该 approval ID 永不可恢复、批准或消费；以后重提必须使用新 ID。
INVALIDATED消费前复核发现批准时绑定的 exact PlatformOperatorAssignment 已 revoked，或关联 User 已 disabled；保存 invalidated_at 与 closed-enum reason code。pointer 不变，即使之后重新授权也必须使用新 approval ID。
EXPIRED24 小时到期。只写平台审计；不切换、不影响 run。需要新 approval ID 才能继续。
CONFLICTED当前 pointer 不再等于 expected-current；拒绝旧批准，写失败审计。需新 request + 新批准。

状态转换以同一 approval ID 串行化：PENDING 只可进入 APPROVED、REJECTED 或 EXPIRED；APPROVED 只可进入 CONSUMED、CONFLICTED、INVALIDATED 或 EXPIRED，不能再被拒绝。任何终态后的批准或执行都必须拒绝。

v1 验收不变量

可证明的隔离

平台批准不是 user token、agent token、workspace role、Chat Web 操作或 Driver MCP tool。它没有被 LLM 读取、生成、重放或解释的路径。

可证明的版本固定

每个新 run 只在 open_run 成功事务中 pin 当时的唯一默认 release；默认切换永不改写已 open 或已 closed run 的 version / digest。

可证明的单写者

仅空 registry 的 deployment genesis 可在唯一事务初始化 pointer；永久 genesis fence 建立后，只有受信 pipeline 能以 CAS 改 pointer，平台运维只能批准或拒绝 immutable request。所有 genesis、成功、验证失败、明确拒绝、批准者权限失效、过期和冲突均有平台审计或安全 deployment failure evidence。

可证明的一次性启动

全空检查、完整 bundle validation 与可信根写入必须同一受 fence 的初始化流程完成；任何部分失败都没有可服务的半初始化 registry。成功后 bootstrap endpoint 永久拒绝，不能成为绕过 Operator / pipeline 的恢复工具。

可证明的接口语义一致

每个 ready/current build 固定同一 InterfaceContractBundle、DomainErrorEnvelope、ExtensionGovernanceMatrix、PolicyApplicationMatrix 与 DependencyHealthPolicy digests；跨 HTTP / gRPC / MCP 的同一错误有同一 retry / authority 语义，authority-bearing unknown 值 fail closed，每项 policy 的 pin / current-recheck、收紧／放宽与审计行为都有可执行 fixture，局部依赖故障只关闭矩阵声明的 route。RunControl pointer 变化不能改写这些 deployment contract。

明确延期的能力

双人 / N-of-M 签核、职责分离、平台运维控制台与用户 / workspace 自定义 run-control 协议均不属于 v1。
